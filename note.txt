Object File 목적 파일 : 
소스 파일을 컴파일해서 만들어지고, 소스 코드가 변경되지 않았다면 컴파일 과정 없이 전에 만들어 놓은 목적 파일을 그대로 사용해서 실행 파일이 만들어집니다.

목적파일의 치명적인 단점 : 
목적 파일에 포함되어 있는 함수의 내용이 실제 사용 여부와 상관없이 모두 실행 파일에 포함된다는 점.

헤더파일이 왜 필요할까?
: c언어가 서로 다른 소스파일에 있는 함수를 참조하려면 함수 원형을 알아야 컴파일 할 수 있다. 그런데 만약 파일에 함수가 4개정도 밖에 없다면 상관이 없지만, 막 100개 이렇게 되버리면 100개를 일일이 선언해야 한다. 그래서 함수 원형들을 특정 파일에 미리 선언해 두고 사용하는데, 이것을 헤더 파일이라고 한다.
#include <stdio.h>의 stdio.h도 헤더 파일임.

#include옆에 " "이거는 사용자가 만든 헤더 파일이라고 생각하고, < >이거는 vs가 제공하는 헤더파일이라고 생각하기 때문에 stdio.h는 가능하면 < >이걸 쓰는게 좋음.

#define 전처리기 : 상수나 명령문을 치환하는 문법
ex) #define MAX_COUNT 3
: 컴파일러가 소스파일에서 MAX_COUNT 단어가 나올 때 마다 모두 3으로 바꿔서 번역

ex) #define POW_VALUE(a) (a*a)
     int date=POW_VALUE(3);
: 3*3이 되어서 data변수에는 9가 들어감.
